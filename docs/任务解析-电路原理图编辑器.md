# 《工业软件创新训练 I》综合设计任务解析

> 课题：**电路原理图编辑器设计与实现** ｜ 难度系数 1.0 ｜ 2025 级 · 工业软件方向
> 解析依据：桌面 `综合设计工业软件` 文件夹内全部文件（任务书 docx、任务描述 pptx、数字电路 pptx、wxWidgets pptx/PDF、Logisim 2.7.1、分组名单 xlsx）

## 一、一句话结论

**你们要做的是一个"类 Logisim"的电路原理图编辑器（画原理图 + 逻辑仿真 + 导出网表），但本学期被考核的重点不是代码，而是"可行性研究 + 需求分析 + 系统设计"三份脑力成果，最终以《综合项目报告》和答辩的形式交付。**

任务书原文（第 40 行）已写明：

> 进阶式挑战性综合项目 I 面向低年级学生开设，要求学生在学习相关课程后参与一个相对简单小型软件工程项目，**工作重点在于学生利用软件工程的思想进行可行性研究、需求分析与系统设计（也可以要求同学完成系统实现阶段，但不纳入考核）**。

这句是整份任务书里最重要的一句话——它决定了你的时间该花在哪。

## 二、要做的"产品"是什么（6 个模块）

任务描述 PPT 第 2 页给出的总体任务：**电路原理图编辑器设计与实现**。拆成 6 个子任务：

| # | 模块 | 具体要求 | 性质 |
|---|------|----------|------|
| 任务 1 | **硬件电路基础** | 学习数字电路基础，理解逻辑电路设计基本原理 | 知识储备，不是交付件 |
| 任务 2 | **用户界面模块** | 基于 **wxWidgets** 做图形界面：菜单、工具栏、元件库（树形结构）、绘图区、属性表 | 设计+可实现 |
| 任务 3 | **元件库模块** | 内置预定义电子元件（与门/或门/非门/触发器…），并支持用户**自定义元件** | 数据结构设计 |
| 任务 4 | **绘图与编辑模块** | 元件放置、移动、连线、缩放等交互编辑功能 | 核心交互 |
| 任务 5 | **文件功能/导出模块** | 设计并实现**网表（netlist）结构**，支持设计文件导入导出；导出**标准网表文件**，且该文件能被 **PCB 软件**加载进入后续流程 | 格式与接口设计 |
| 任务 6 | **电路仿真模块** | 实现**动态的电路信号传播与实时逻辑仿真** | 算法核心 |

> 注：任务描述 PPT 把任务 5 叫"文件功能模块"，任务书里叫"文件导出模块"，是同一件事。

**界面参照物就是 Logisim**（PPT 第 5 页明确写了"界面组成元素：Logisim 设计和模拟数字逻辑电路工具"，第 6–8 页贴的是 Logisim 主界面、元件库、绘制半加器的截图）。文件夹里那个 `Logisim2.7.1.cn-v3`（免 Java 中文版，自带 JRE）就是给你们当**竞品对标 + 需求来源 + 验证工具**用的。

**涉及知识点**（任务书第 27–32 行，报告里可直接引用）：
- 程序设计与算法基础：数据结构的设计与应用、文件操作
- 人机界面设计：基于桌面操作系统的应用界面设计
- 计算机图形学：计算机绘图、2D 图像渲染
- 操作系统：系统事件响应式编程技术
- 电子电路基础：逻辑代数、组合逻辑电路

## 三、真正的考核点（决定分数的地方）

任务书背页的"毕业要求指标点映射图"列了 4 条工作内容，对应 2 个指标点：

| # | 要求你做到 | 对应指标点 |
|---|-----------|-----------|
| 1 | 可行性研究阶段：针对一个问题找出**多种可选方案**，对比后选出**最优方案**，并**阐述原因、预测结果**；体现通过**文献分析**找出可替代方案的能力 | **GR2.2** 学生能认识到解决问题有多种方案可选择<br>**GR2.3** 学生能分析文献寻求可替代的解决方案 |
| 2 | 需求分析阶段：对待开发软件的需求进行分析并给出**详细定义** | （同上条目） |
| 3 | 综合项目报告要体现**小组团队分工**以及**每位组员独立完成的工作** | — |
| 4 | 答辩阶段：能陈述发言，清楚表达"针对问题提出的多种方案""在多种方案中寻找最优方案的思路与**验证过程**" | — |

翻译成大白话：

1. **不能只写一种方案。** 每个关键技术选择（UI 框架、元件库组织方式、绘图/渲染方式、网表格式、仿真算法、文件持久化格式）都要写成"方案 A / 方案 B / 方案 C → 评价维度 → 选谁 → 为什么 → 预期效果"的对比表。
2. **要有参考文献。** wxWidgets 官方文档、Logisim 论文/源码、KiCad/Eagle/SPICE 网表规范、图形学教材等都算，正文里要引用。
3. **分工必须落到人。** 报告里要有一张"组员 → 负责模块 → 独立产出"的表，答辩时每人要讲自己那块。
4. **答辩要讲"验证"。** 不只是"我选了 A"，而是"我用什么方式验证 A 更优"（原型 demo、小实验、性能对比、格式兼容性实测…）。

## 四、阶段与交付物清单

```
阶段 1  可行性研究  ──► 多方案对比 + 最优方案 + 依据 + 预期结果
阶段 2  需求分析    ──► 详细需求定义（功能/非功能/用例/数据需求）
阶段 3  系统设计    ──► 总体架构 + 模块划分 + 数据结构 + 界面设计 + 接口(网表格式)
阶段 4  （可选）实现 ──► 不纳入考核，但做了答辩加分、也是"验证过程"的证据
阶段 5  综合项目报告 ──► 含团队分工与每人独立工作
阶段 6  答辩        ──► 陈述 + 问答
```

报告与答辩是**必交/必考**，代码是**加分项**。因此建议：先交齐文档，再用课余时间做可运行的演示原型（哪怕只做出界面 + 元件库 + 拖放连线，答辩时演示效果极好）。

## 六、建议的落地方案（报告里"最优方案"可以这样写）

### 6.1 技术选型（每一项都是"多方案对比"的好素材）

| 决策点 | 候选方案 | 建议选择与理由 |
|--------|----------|----------------|
| 开发语言/框架 | ① wxWidgets + C++（任务指定）② Qt + C++ ③ Electron/Web 前端 ④ Python + tkinter/PyQt | 选 ①：课程指定、跨平台、原生性能、与 VS2022 现成环境匹配（你桌面已装 Visual Studio 2022） |
| 元件库组织 | ① 硬编码类继承体系 ② 树形配置文件（XML/JSON）加载 ③ 数据库 | 选 ②：满足"用户自定义元件"需求，扩展无需重编译；树形结构与 UI 元件库面板天然对应 |
| 绘图/渲染 | ① wxDC 直接绘制 ② wxGraphicsContext（抗锯齿）③ OpenGL 画布 | 选 ②：2D 矢量绘制、有抗锯齿、复杂度适中；元件多时再考虑①优化 |
| 交互模型 | ① 事件响应式（鼠标/键盘事件回调）② 状态机 Command 模式 | 选 ②：放置/移动/连线/缩放是典型多状态交互，Command 模式天然支持 Undo/Redo |
| 网表格式 | ① 自定义 JSON ② SPICE netlist ③ EDIF ④ KiCad/Protel 网表 | 建议 **JSON 存自己的工程文件 + SPICE/标准网表导出**双轨：JSON 保 GUI 信息（坐标/外观），SPICE 满足"能被 PCB 软件加载" |
| 仿真算法 | ① 事件驱动（信号变化触发重算）② 每时钟周期全图遍历 ③ 拓扑排序求值 | 选 ①+③：组合逻辑用拓扑排序一次求值，时序逻辑（触发器/寄存器）按事件驱动推进时钟 |
| 图形数据结构 | ① 邻接矩阵 ② 邻接表 ③ 图 + 引脚级节点表 | 选 ③：以"引脚"为节点、以"导线"为边，才能正确处理一端多分支、交叉不连接等原理图语义 |

### 6.2 需求分析要覆盖的内容

- **功能需求**：文件（新建/打开/保存/另存/导入导出网表）、编辑（选中/移动/复制/删除/撤销重做）、绘图（放置元件/画导线/放置节点/缩放平移）、元件库（浏览/搜索/自定义元件）、属性（元件参数/标号/位置编辑）、仿真（运行/暂停/单步/时钟设置/信号观测）
- **非功能需求**：性能（1000 元件下操作流畅）、易用性、跨平台、可扩展（插件式元件）、可靠性（异常保存）
- **用例图 + 主要用例描述**（放置元件、连线、运行仿真、导出网表）
- **数据需求**：工程文件格式、元件库格式、网表格式的字段定义

### 6.3 系统设计要产出的图

1. 总体架构图（UI 层 / 领域模型层 / 仿真引擎 / IO 持久化层）
2. 模块划分图（对应 6 个模块）
3. 核心类图（Component / Port / Wire / Pin / Circuit / Sheet / Simulator / NetlistWriter）
4. 关键流程图（放置元件流程、连线合法性判定流程、仿真推进流程）
5. 界面设计图（主窗口布局：菜单 + 工具栏 + 左侧元件库树 + 中间绘图区 + 右侧属性表 —— 直接对标 Logisim 截图）
6. 网表导出示例（半加器原理图 → 网表文本）

### 6.4 建议分工模板（5 人组）

| 组员 | 负责模块 | 独立完成的工作 |
|------|----------|----------------|
| 组长 | 总体架构 + 可行性研究统稿 | 方案对比矩阵、文献调研、进度管理 |
| 成员 B | 界面模块 | wxWidgets 主窗口/菜单/工具栏/属性表设计 |
| 成员 C | 元件库模块 | 元件元模型设计、预定义库清单、自定义元件机制 |
| 成员 D | 绘图与编辑模块 | 图形数据结构、交互状态机、渲染方案 |
| 成员 E | 文件/网表 + 仿真模块 | 网表格式定义、导出器设计、仿真算法（拓扑排序/事件驱动） |

## 七、容易踩的坑

1. **把重心放在写代码上** → 代码不纳入考核，报告和答辩才是得分点。
2. **可行性研究只写一种方案** → 直接丢 GR2.2/GR2.3 的分。
3. **报告里没有"每人独立完成的工作"** → 任务书第 3 条明确要求。
4. **答辩讲不清"为什么选这个方案""怎么验证的"** → 任务书第 4 条明确要求。
5. **网表格式自己随便定** → 任务 5 要求"标准网表，可被 PCB 软件加载"，要引规范（SPICE/EDIF/KiCad）。
6. **忽略"缩放"和"用户自定义元件"** → 任务 3、4 里点名写了，需求分析必须覆盖。
7. **界面设计与 Logisim 脱节** → PPT 已经给了参照物，照着做不会偏。
