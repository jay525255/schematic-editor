## 5. 引脚级网络模型（任务 5 的核心）

### 5.1 数据结构

```
ComponentInstance ── 元件实例 ── 含 N 个 Pin
   Pin：name(A/Y/1/GND)、dir(输入/输出/无源)、side(左/右/上/下)、slot、count
Wire              ── 一条轴对齐线段（折线 = 多条首尾相接的导线）
Net               ── 电气连通的引脚集合 + 该网络的全部连接点
NetGraph          ── Build() 的结果：全部网络 + 导线→网络 + 引脚→网络 + 连接点位置
```

### 5.2 连通规则（与 KiCad / Logisim 一致）

| 情形 | 是否连通 | 说明 |
|------|----------|------|
| 两条导线端点重合 | ✅ | 并查集同坐标即同节点 |
| 导线端点落在另一条导线上 | ✅ | **T 型连接**，自动画实心连接点 |
| 引脚落在导线上 | ✅ | 元件引脚接到导线中间 |
| 两条导线十字交叉 | ❌ | **不连通**（原理图惯例：交叉不连接） |
| 两个引脚坐标重合 | ✅ | 直接对接 |

实现：把每个"连接点"（引脚外端、导线端点、连接点）建成图节点，同坐标共用一个节点；
每条导线合并自身两端；再把所有落在某条导线**内部**的点与该导线合并。
十字交叉处没有任何"点"，所以天然不会误连。

### 5.3 算法

- **并查集（Union-Find）** 求连通分量，带路径压缩，复杂度近似 O(N α(N))
- 网络自动命名 `N1 / N2 / …`；若网络连到 `GND` / `VCC` 元件则直接用该名字
- 连接点判定：某点上"接触"的导线数 ≥ 3（穿过算 2 股）

### 5.4 网表格式

以 `*` 开头的注释行 + 三段内容：网络清单 / 元件清单 / SPICE 风格元件行。
样例见 `docs/sample-netlist.net`。格式定义集中在 `NetBuilder::ToNetlist()` 一个函数里，
**换成 Protel / KiCad / EDIF 格式只需替换这个函数**，模型层与界面层无需改动。

### 5.5 电气规则检查（ERC）

三项：悬空引脚、悬空导线端点、只连了一个引脚的孤立网络。
样例见 `docs/sample-erc-report.txt`。

## 5A. 撤销 / 重做的方案选择（写报告可直接用）

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **A. Command 模式** | 每种操作封装成一个命令对象，记录"做了什么 + 怎么反做" | 内存占用小；可以合并连续操作 | 每种操作都要单独实现 `Undo()`；**漏掉一种操作就是 bug**（比如移动、批量删除都要各写一份） |
| **B. 快照式（本工程采用）** | 每次改动前把整份文档（元件表 + 导线表 + 编号计数器）复制一份压栈 | 实现简单、**绝不会漏操作**；撤销就是整体替换，逻辑上不会出错 | 内存开销与文档规模成正比；不能按"操作类型"做精细处理 |
| C. 逆操作记录 | 只记录"反着做要执行的动作" | 内存最省 | 逆操作比正操作还难写（删元件要恢复它的所有导线和位号） |

**为什么选 B**：本工程一份原理图的规模是**几百个元件量级**，
一个快照大约几十 KB，100 步也只有几 MB，内存完全不是瓶颈。
而 Command 模式要为放置 / 移动 / 连线 / 删除 / 清空各写一个命令类并各自保证正确性，
**在课程项目的时间预算下性价比明显更低**。

实现要点（`SchematicCanvas::PushUndo` / `Undo` / `Redo` / `ApplySnapshot`）：

- 快照内容：`components` + `wires` + `nextComponentId` + `nextWireId` + `refCount`
  —— 少存任何一个都会导致"撤销后再放新元件，位号和之前撞车"
- **拖动移动只在"真正开始移动"时压一次快照**，单纯点击选中不产生撤销步
- 一次导线单击可能生成 1~2 条线段，只压一次快照 → 撤销时整步回退
- 有新的操作时清空重做栈（标准撤销语义）

### 6.1 用户自定义元件（`components.xml`）

程序目录下放一份 `components.xml`，第一次运行自动生成带注释的模板：

```xml
<ComponentLibrary version="1">
  <Category name="用户自定义">
    <Component name="三输入与门" refPrefix="U" description="Y = A · B · C（示例）"
               inputs="3" outputs="1" kind="Logic" width="70" height="46"
               footprint="DIP-14" value="AND3"/>
  </Category>
</ComponentLibrary>
```

- 字段：`name / refPrefix / description / inputs / outputs / kind / width / height / footprint / value`
- `kind` 取 `Logic`（左入右出）、`Passive`（左右两端）、`Power`（底部单脚）、`Port`（端口/标签）
- **名称与内置元件相同 = 覆盖内置元件的字段**（例：填 `电阻`、`value=1k`，默认值就变了）
- 加完元件后：菜单 **工具 → 重新加载元件库**（或重启）即可看到，树里带 ★ 标记
- 也可以完全在界面里做：**工具 → 元件库管理...**（新建 / 删除 / 改字段 → 保存并应用）

## 8. 工程里的关键设置（写报告时可作为"技术方案"素材）

### 8.1 头文件顺序：`include\msvc` 必须排在 `include` 之前

```xml
<AdditionalIncludeDirectories>$(WXWIN)\include\msvc;$(WXWIN)\include;...</AdditionalIncludeDirectories>
```

`include\msvc\wx\setup.h` 是 MSVC 专用的**包装头**：自动推导真正的 `wx/setup.h` 路径，
并用 `#pragma comment(lib, ...)` **自动链接**所有需要的 wx 库与系统库。
所以工程里**不需要**手写一长串 `.lib`。

### 8.2 `/utf-8`：中文源码必须显式声明编码

本机代码页是 **GBK(936)**。源码里的 `L"新建原理图"` 若按 GBK 解析，UTF-8 字节会被拆成非法序列，
直接报 `error C2001: 常量中有换行符`。双保险：源码存成 **UTF-8 with BOM** + 编译加 `/utf-8`。

### 8.3 运行库必须与 wx 库一致

| 配置 | RuntimeLibrary | 效果 |
|------|----------------|------|
| Debug | `MultiThreadedDebugDLL` | `/MDd` |
| Release | `MultiThreadedDLL` | `/MD` |

误改成 `/MT` 会出现大量 `LNK2005 xxx 已经在 msvcrt.lib 中定义`。

### 8.4 资源文件必须包含 `wx/msw/wx.rc`

嵌入 **Common Controls v6 清单**，让窗口使用 Win10/11 现代视觉样式。
资源编译器的附加包含目录要加 `$(WXWIN)\lib\vc_x64_lib\mswu`（Debug 用 `mswud`），
因为 `rcdefs.h` 是构建时生成到 `lib\...\mswu\wx\msw\` 下的。

### 8.5 引脚必须落在网格上

`PinAnchor()` 会把引脚沿边的偏移量对齐到 10 单位网格，`PlaceComponent()` 把元件左上角对齐网格。
**否则画导线时"吸附到引脚"和"吸附到网格"会打架**：点一下引脚（非网格坐标）、
再点一下空白（网格坐标），就会多出一段 1~3 单位的折角，
表现为"导线数比预期多"和"网络被错误合并"。

## 10. 常见坑速查

| 现象 | 原因 | 解决 |
|------|------|------|
| `error C2001: 常量中有换行符` / 中文变乱码 | 源码无 BOM 且被按 GBK 解析 | 存成 UTF-8 with BOM，并保留 `/utf-8` |
| `无法打开包括文件: "wx/wx.h"` | `WXWIN` 未设置或 `include\msvc` 不在最前 | 检查 `WXWIN` 与附加包含目录顺序 |
| `LNK1104: 无法打开文件 wxmsw32ud_core.lib` | 配置与已编译的 wx 库不匹配 / 选了 Win32 / 定义了 `WXUSINGDLL` | 用 `Debug\|x64` 或 `Release\|x64` |
| `LNK2005 xxx 已经在 msvcrt.lib 中定义` | 运行库用了 `/MT` | 改回 `/MD` 或 `/MDd` |
| `LNK1168: 无法打开 exe 进行写入` | 上一次运行的程序还开着 | 先结束进程再编译 |
| 窗口是老式灰白外观 | 没有编译 `.rc` 或未包含 `wx.rc` | 确认 `res\SchematicEditor.rc` 在工程里 |
| `wxToolBar::AddTool` 参数不匹配 | wx 3.2 没有 `AddTool(id, 文本, 位图, 禁用位图, 提示)` 五参重载 | 普通工具用 `AddTool(id, 文本, 位图, 提示)` |
| 菜单「退出」「打开」点了没反应 | `Bind` 的动态处理器**后绑定的先匹配**，兜底区间写在具体绑定之后会吃掉它们；且 `wxID_OPEN(5000) < wxID_NEW(5002)` | 兜底绑定用 `[wxID_LOWEST, …]` 整段 + `switch` 分发 |
| Debug 启动弹 `wxPropertyGrid item with name "XXX" already exists` | `wxStringProperty(label, wxPG_LABEL, …)` 会把 label 当内部名称，分类名与属性名相同就重名 | 用自动编号生成唯一内部名（`@row%d` / `@cat%d`） |
| Debug 里一点搜索框就弹 `wxWidgets Debug Alert`（Release 却正常） | 用 `wxAutoBufferedPaintDC` 的窗口没在构造函数里 `SetBackgroundStyle(wxBG_STYLE_PAINT)` | 构造里补一行；排查用 `SE_ASSERT_LOG=1` 把断言写进 `assert.log`（已修） |
| Debug 画导线时闪退，事件日志异常码 `0xc000041d` | `DrawComponents` 里**先 `GetTextExtent` 后 `SetFont`**，wxGDI+ 断言 `no valid font set`；断言弹窗发生在 `WM_PAINT` 回调里导致异常穿透 | **先 `SetFont` 再 `GetTextExtent`**（已修） |

> **定位断言的手段**：`wxSetAssertHandler()` 可以接管断言，把 `file/line/cond/msg`
> 写进日志文件并直接返回（不弹窗），比读弹窗里的文字方便得多。
> 本工程已经把这条路子做进 `minimal.cpp:35`：**设环境变量 `SE_ASSERT_LOG=1`** 再启动，
> 断言就会写进 exe 旁边的 `assert.log` 并继续执行；不设这个变量时行为完全不变。
> `0xc000041d`（STATUS_FATAL_USER_CALLBACK_EXCEPTION）就是"回调里抛出了未处理异常"，
> 在 wx 里十有八九是**绘制回调中的断言弹窗**导致的。
